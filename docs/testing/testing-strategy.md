## 1. Поточний статус тестування
На поточному етапі в проєкті розгорнуто автоматизований набір модульних тестів на базі фреймворку **pytest**.
- **Структура тестів:**
  - `tests/test_auth.py`: Автентифікація, випуск та перевірка JWT-токенів, PBKDF2-хешування паролів, матриця ролей, зміна паролів (59 тестів).
  - `tests/test_stages.py`: Керування Канбан-етапами дошки (FR-003, FR-024), сортування, права доступу, валідація цілісності (16 тестів).
  - `tests/test_mentors.py`: Запрошення менторів, валідація токенів, перевірка read-only обмежень (3 тести).
  - `tests/test_validators.py`: Бізнес-валідація посилань на вакансії та захист від SSRF (3 тести).
  - `tests/test_properties.py`: Property-based тести на базі Hypothesis (2 тести).
- **Загальна кількість модульних тестів:** 83 тести (100% успішне проходження).
- **Ізоляція:** Тести використовують in-memory тестові дублери (`InMemoryRepository`), фікстури pytest та моки (`unittest.mock.Mock`), що забезпечує виконання всього набору за <25 секунд без потреби у запущеній СУБД.

## 3. Плани подальшого розвитку рівнів тестування (Testing Pyramid)

1. **Інтеграційні тести (Integration Testing):**
   - Тестування кінцевих точок API через `httpx.AsyncClient` / `TestClient` з тестовою базою даних PostgreSQL у Docker Compose.
   - Перевірка виконання Alembic-міграцій (upgrade / downgrade) та збереження консистентності зовнішніх ключів.
2. **Системні та приймальні тести (E2E / Acceptance):**
   - Автоматизація користувацьких сценаріїв (US-001 – US-008) через Playwright / Cypress для перевірки drag-and-drop переміщення карток на Канбан-дошці.
   - Тестування взаємодії кандидата та ментора в режимі реального часу.
3. **Нефункціональне тестування:**
   - **Продуктивність (Performance):** Навантажувальне тестування ключових ендпоінтів через Locust / k6 для підтвердження NFR (PERF-1: завантаження дошки $\le 1$ с при 100 картках; PERF-2: відповідь API $\le 200$ мс для 95% запитів).
   - **Безпека (Security):** Автоматизоване сканування на вразливості через OWASP ZAP, Bandit (SAST) та перевірка ролей BOLA/IDOR.

## 4. Інтеграція в конвеєр CI/CD
Тестування повністю інтегровано в GitHub Actions ([.github/workflows/ci.yml](file:///c:/Users/Nikita/Monkey-Business-project/.github/workflows/ci.yml)):
1. **Тригери:** Запуск на кожен `push` та `pull_request` у гілку `main`.
2. **Кроки пайплайну:**
   - Встановлення залежностей проєкту та середовища тестування.
   - Запуск `pytest` з генерацією звітів у форматах terminal, HTML та XML (`coverage.xml`).

   - Автоматичне додавання резюме покриття до GitHub Actions Job Summary.
   - Збереження звітів `htmlcov` як артефактів білду.

# Бонуси

### Бонус №1: Тести на основі властивостей (Property-Based Testing)
У тестовий набір додано модуль `tests/test_properties.py` з використанням бібліотеки **Hypothesis**:
- **Властивість 1 (Round-trip інваріантність хешування паролів):**
  - *Формулювання:* «Для будь-якого випадково згенерованого текстового пароля $s$ функція верифікації `_verify_password(s, _hash_password(s))` завжди повертає `True` для оригінального пароля і `False` для будь-якої його модифікації».
  - *Чому має виконуватися:* Це фундаментальний криптографічний інваріант безпеки автентифікації: хеш повинен однозначно верифікуватися лише оригінальним входом незалежно від набору символів (включаючи пробіли, емодзі, Unicode).
- **Властивість 2 (Монотонність сортування етапів):**
  - *Формулювання:* «Для будь-якої випадкової перестановки цілочисельних індексів `order_index`, відсортований список гарантує, що для кожного елемента $i$ виконується $order\_index_i \le order\_index_{i+1}$».
