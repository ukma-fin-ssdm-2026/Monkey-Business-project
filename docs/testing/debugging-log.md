# Журнал налагодження — Лаб06

## Помилка: видалення непорожнього етапу (FR-024)

**Симптом.** Під час контрольного челенджу з `delete_stage` тимчасово прибрано перевірку `repos.stages.has_cards(stage_id)`. Модульний тест очікує `ConflictError`, але отримує `Failed: DID NOT RAISE`: бізнес-логіка дозволяє видалити етап із картками. У PostgreSQL зовнішній ключ `ON DELETE RESTRICT` додатково захищає цілісність; без перевірки роутера клієнт не отримує передбачуваний доменний конфлікт 409.

**Відтворення.** На справному коді тест проходить. Після вилучення лише цієї перевірки запущено:

```bash
python -m pytest -q -o addopts='' tests/test_stages.py::test_delete_stage_raises_conflict_when_stage_has_cards
```

Результат з навмисною помилкою: **1 failed**; після відновлення перевірки: **1 passed**. Команда вимикає загальний поріг лише для цього одиничного діагностичного прогону.

**Ізоляція й причина.** Фікстури створюють дошку власника та етап із картками. Контроль доступу залишається справжнім, сховище замінене in-memory дублером. Збій ізольовано до виклику видалення без перевірки наповненості:

```python
# src/api/routers/stages.py — відновлена перевірка
if repos.stages.has_cards(stage_id):
    raise ConflictError("Неможливо видалити етап, у якому є картки")
repos.stages.delete(stage_id)
```

**Виправлення та регресія.** У фінальному коді перевірку відновлено. [Регресійний тест](../../tests/test_stages.py) `test_delete_stage_raises_conflict_when_stage_has_cards` перевіряє виняток, повідомлення та збереження етапу. Він уже був у знімку й повторно перевірений навмисною помилкою. Сусідній `test_delete_stage_success_when_stage_has_no_cards` перевіряє дозволене видалення. Повний фінальний прогін: **124 passed**.

**Урок.** Перевіряти разом дозволену операцію та її заборонений граничний випадок. Зовнішній ключ захищає дані, а доменна перевірка забезпечує зрозумілу відповідь клієнту. Модульний тест відтворює причину без запуску БД і frontend.

## Реальні дефекти, знайдені під час перевірки набору

- `User.failed_login_attempts` був відсутній у `UserRow`: додавання/оновлення користувача викликало `TypeError`. Нові [регресійні тести](../../tests/test_sql_repository.py) спочатку падали; додано поле ORM і міграцію `0003`. Дві регресії перевіряють запис через `add` та читання лічильника; мапінг використовується також у `save`.
- Для видаленого ментора код створював `EmailStr` із порожнього рядка. Замість xfail тепер звичайні [тести](../../tests/test_mentors.py): список пропускає відсутнього користувача, перегляд запрошення повертає `NotFoundError`, прийняття заборонене без зміни статусу.
