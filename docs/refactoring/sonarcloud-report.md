## Рефакторинг секрету PostgreSQL у Docker Compose

1. **Запах коду:** хардкод конфігурації та секрету — пароль PostgreSQL мав
   значення за замовчуванням у `docker-compose.yml`, а отже міг потрапити в
   середовище запуску та історію конфігурації.
2. **Техніка:** Replace Magic Value / Externalize Configuration — пароль
   замінено на обов'язкову змінну `${POSTGRES_PASSWORD:?...}`. Значення
   передається локально через `.env` або змінну середовища; у CI пароль
   PostgreSQL не визначається.
3. **Що лишилось незмінним:** назви сервісів, порти, том `pgdata`, healthcheck,
   мережа `backend`, значення `POSTGRES_DB` і `POSTGRES_USER` за замовчуванням,
   URL підключення API та логіка запуску контейнерів.
4. **Який тест це доводить:** `tests/test_docker_compose_security.py`
   перевіряє, що пароль у Compose є лише обов'язковою зовнішньою змінною без
   fallback-значення, а файли `.github/workflows/*.yml` не визначають
   `POSTGRES_PASSWORD`.

## Рефакторинг сумісності dev-залежностей

1. **Запах коду:** застаріла/недоступна версія залежності — `mutmut==2.5.1`
   не мала доступного дистрибутива для binary-only встановлення в pipeline.
2. **Техніка:** Upgrade Dependency Version — залежність оновлено до
   `mutmut==3.8.1`, яка постачається як Python wheel.
3. **Що лишилось незмінним:** призначення mutation testing, решта списку
   dev-залежностей і обмеження `--only-binary=:all:`.
4. **Який тест це доводить:** `pip download --only-binary=:all: --no-deps
   -r requirements-dev.txt` успішно завантажує всі дев-залежності.
