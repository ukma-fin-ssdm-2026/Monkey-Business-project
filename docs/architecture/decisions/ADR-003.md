# ADR-003: Вибір системи моніторингу (Prometheus + Grafana)
**Статус:** Затверджено
**Дата:** 2026-09-21

### Контекст
Для забезпечення надійності системи та тестування додатку нам необхідно збирати технічні метрики (завантаження ресурсів, кількість запитів) і мати можливість графічного відображення для зручного аналізу.

### Рішення
Використовувати **Prometheus** для збору метрик та **Grafana** для їх графічного відображення.

### Наслідки
*   **Плюси:** Grafana надає найкращі інструменти для графічної візуалізації; Prometheus є стандартом індустрії з потужною системою алертів.
*   **Застереження:** Необхідно налаштувати експортери на бекенді та БД.
*   **Мінуси:** Додаткові витрати ресурсів сервера на роботу моніторингу; потрібно вивчати мову запитів PromQL.

### Відхилені альтернативи
1.  **ELK Stack (Elasticsearch, Logstash, Kibana):** Відхилено. ELK ідеально підходить для аналізу текстових логів, але для наших потреб (виключно графічне відображення числових метрик) він є занадто "важким".
2.  **Вбудовані засоби хмарних провайдерів:** Відхилено. Щоб уникнути прив'язки до конкретного провайдера (vendor lock-in) на етапі прототипування.

## Використання ШІ

- **Інструмент:** Gemini
- **Застосування:** допомога у формулюванні та структуруванні ADR.
- **Верифікація:** ADR верифіковані, скориговані та затверджені командою вручну.
