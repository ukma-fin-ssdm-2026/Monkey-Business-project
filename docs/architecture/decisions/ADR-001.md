# ADR-001: Вибір архітектури Frontend-додатку (React + PWA)
**Статус:** PWA ще не реалізовано
**Дата:** 2026-09-21

### Контекст
Для розробки користувацького інтерфейсу нашого додатку необхідна технологія, що дозволить створити динамічну Канбан-дошку. Ключовою вимогою (REL-2) є підтримка офлайн-синхронізації та збереження працездатності при перебоях з мережею, що вимагає ефективного управління станом (state) на стороні клієнта.

### Рішення
Використовувати бібліотеку **React** для побудови інтерфейсу у комбінації з технологією **PWA (Progressive Web App)**.

### Наслідки
*   **Плюси:** Ефективне управління станом (state) Канбан-дошки; PWA дозволяє кешувати ресурси та підтримувати роботу додатку офлайн (через Service Workers); PWA можна встановити на телефон як нативний застосунок.
*   **Застереження:** Необхідно ретельно продумати механізм синхронізації локального стану з сервером після виходу з офлайну.
*   **Мінуси:** Збільшений розмір бандлу для першого завантаження; дещо складніше SEO.

### Відхилені альтернативи
1.  **Vanilla JS / jQuery:** Відхилено, оскільки реалізація складного управління станом Канбан-дошки "з нуля" буде занадто довгою і важкою в підтримці.
2.  **Нативні мобільні додатки (iOS/Android):** Відхилено через надмірні витрати часу. Технології PWA повністю достатньо, щоб покрити наші потреби в офлайн-роботі.
