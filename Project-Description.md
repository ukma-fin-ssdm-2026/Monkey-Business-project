# Трекер підготовки до технічних співбесід (Tech Interview Board)

## Опис ідеї проєкту

Пошук роботи в IT зазвичай означає паралельне ведення десятків відгуків на вакансії, кожен з яких перебуває на своєму етапі (відгук, скринінг, технічне інтерв'ю, офер) і супроводжується власним набором вимог, тестових завдань і фідбеку від рекрутерів. Без систематизації кандидати втрачають дедлайни, забувають деталі вакансій і не бачать реальної картини свого прогресу. **Tech Interview Board** - це Канбан-орієнтований інструмент, який вирішує цю проблему: користувач додає вакансії як картки, переміщує їх між етапами воронки найму, зберігає вимоги вакансії та посилання на тестові завдання, а також веде нотатки з фідбеком від рекрутерів.

Крім особистого використання, система передбачає можливість поділитися прогресом із ментором чи наставником, який може переглядати дошку та залишати коментарі — це наближає проєкт до реального інструменту для кар'єрного супроводу, а не просто персонального чек-листа.

## Ролі користувачів

| Роль | Опис можливостей |
|---|---|
| **Кандидат (Job Seeker)** | Основний користувач. Створює та редагує картки вакансій, переміщує їх між етапами, додає вимоги, посилання на тестові завдання, нотатки та фідбек. Запрошує ментора до перегляду своєї дошки. |
| **Ментор (Mentor)** | Запрошується кандидатом. Має доступ лише для перегляду дошки та залишення коментарів/фідбеку до карток; не може редагувати чи видаляти вакансії. |
| **Адміністратор (Admin)** | Керує обліковими записами користувачів, глобальними налаштуваннями системи (наприклад, стандартним набором етапів воронки, лейблами), модерує звернення підтримки. |

## Ключові функції (високорівневий список)

1. Реєстрація/автентифікація та керування профілем користувача.
2. Канбан-дошка з drag-and-drop переміщенням карток вакансій між етапами (Відгук → Скринінг → Технічне інтерв'ю → Офер).
3. Створення та редагування картки вакансії: вимоги, посилання на тестові завдання, дедлайни.
4. Ведення нотаток і фідбеку від рекрутерів для кожної вакансії.
5. Запрошення ментора для перегляду дошки та коментування карток.
6. Нагадування про наближення дедлайнів (тестові завдання, співбесіди).
7. Проста аналітика: конверсія між етапами, кількість активних заявок за період.

## Міні-ТЗ

### 1. Призначення системи
Tech Interview Board - веб-система для кандидатів, які активно шукають роботу в технічній сфері, що дозволяє систематизувати процес пошуку: відстежувати статус кожної вакансії на Канбан-дошці, зберігати пов'язану інформацію (вимоги, тестові завдання, фідбек) в одному місці та залучати ментора для консультацій щодо прогресу.

### 2. Межі системи
**Входить в обсяг семестру:**
- Реєстрація/авторизація користувачів (кандидат, ментор, адміністратор).
- Канбан-дошка з базовими етапами та можливістю drag-and-drop.
- CRUD-операції над картками вакансій (вимоги, посилання, дедлайни, нотатки).
- Механізм запрошення ментора до конкретної дошки з обмеженими правами (перегляд + коментарі).
- Базові нагадування про дедлайни (in-app або email).
- Проста аналітика по дошці (конверсія етапів, кількість активних вакансій).
- AI-асистент для генерації відповідей на тестові завдання чи підготовки до співбесід.

**Не входить в обсяг семестру (поза межами):**
- Автоматичний парсинг/імпорт вакансій з job-бордів (LinkedIn, DOU тощо).
- Інтеграція з календарями (Google Calendar, Outlook) для планування співбесід.
- Мобільний застосунок (лише responsive веб-версія).

### 3. Ролі користувачів і що кожна може робити
- **Кандидат**: повний CRUD над своїми вакансіями та дошкою; керування нотатками й фідбеком; запрошення менторів; перегляд власної аналітики.
- **Ментор**: перегляд дошки(ок), до яких запрошений; додавання коментарів/фідбеку до карток; без права редагування чи видалення даних кандидата.
- **Адміністратор**: керування обліковими записами (блокування/розблокування), налаштування глобальних параметрів системи (стандартні етапи, лейбли), перегляд системних логів/статистики використання.

### 4. Ключові функції
1. Автентифікація та розмежування доступу за ролями.
2. Канбан-дошка з переміщенням карток вакансій між етапами.
3. Керування картками вакансій (вимоги, посилання на тестові завдання, дедлайни).
4. Нотатки та фідбек по кожній вакансії.
5. Запрошення та обмежений доступ ментора до дошки.
6. Нагадування про дедлайни.
7. Базова аналітика прогресу (конверсія по етапах).
8. AI-асистент для підготовки до співбесід

### 5. Нефункціональні вимоги
1. **Продуктивність**: дошка зі 100 картками вакансій повністю завантажується за не більше ніж 1 секунду при 20 одночасних користувачах.
2. **Безпека/приватність**: доступ ментора до дошки обмежується правами "перегляд + коментар"; паролі зберігаються у хешованому вигляді; передача даних відбувається лише по HTTPS.
3. **Надійність**: доступність системи не менше 99% протягом семестру тестової експлуатації; операції з картками (створення/переміщення) не повинні призводити до втрати даних при помилці мережі (retry або локальний кеш).
4. **Зручність використання**: drag-and-drop дошка коректно працює на екранах шириною від 360px (мобільний браузер) без горизонтального скролу.

### 6. Припущення та обмеження
- **Стек**: команда орієнтується на TypeScript/Python екосистему (наприклад, React на фронтенді, FastAPI або аналогічний фреймворк на бекенді) - фінальний вибір буде зафіксовано в Лаб 3.
- **Зовнішні сервіси**: для нагадувань планується використання стороннього email-сервісу або внутрішньої черги задач.
- **Дані**: система не використовує реальні персональні дані третіх осіб (рекрутерів, компаній) поза тим, що вводить сам кандидат вручну.
- **Часові обмеження команди**: команда з 4 осіб (Nazar Sydorchuk, Oleksii Volik, Mykola Vashchenko, Nikita Dyshlyuk), працює за GitHub Flow, зустрічі двічі на тиждень; обсяг розробки розрахований на 10-11 тижнів семестру.
